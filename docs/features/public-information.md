# Public information surfaces

`PUB-001` owns `/media-kit`, `/contact`, `/privacy`, and `/terms`.

- Media kit is one fail-closed publication. Its approved `page/media-kit` record must contain summary and body copy. A published press record in category `media-kit-pdf` must reference exactly one media UUID and carry `version:<value>`. The public safe-media adapter at `/api/public/media/assets/{assetID}` must return that same UUID with `status: ready`, `mime_type: application/pdf`, `use-rights:approved`, a valid update timestamp and an HTTPS `.pdf` URL on a host allowlisted by `API_BASE_URL` or `PUBLIC_MEDIA_HOSTS`. If any part is missing, neither narrative nor download is treated as published and the route is `noindex, nofollow`.
- Contact uses only approved public settings consent and published services. It posts through the enquiry endpoint with an idempotency key, consent version, honeypot and CAPTCHA integration field. No email address, recipient or social handle is hardcoded.
- Privacy and terms use approved published page records. Every record requires `legal-version:<value>`, a calendar-valid non-future `effective-date:YYYY-MM-DD`, a valid content `updated_at`, and stable `subject:*` inventory tags. Privacy requires `purposes-data-use`, `lawful-basis`, `retention`, `cookies`, `enquiries`, `data-subject-rights`, and `contact`; terms requires `site-use`, `asset-use`, `booking-disclaimer`, and `contact`. Privacy also requires approved consent metadata, and both require an approved public email. Missing requirements show conspicuous staging-only incomplete copy outside production, remain `noindex, nofollow`, and fail closed in production.
- Shared integration needs: JK-009 must keep the public enquiry route mounted. JK-008/API integration must expose the documented safe, read-only media DTO without storage keys, provider credentials, or private metadata. Until that endpoint exists, the media kit intentionally remains unavailable.
